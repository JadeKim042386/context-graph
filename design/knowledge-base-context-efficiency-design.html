Evidence-First Knowledge Base: Context Efficiency

A standalone knowledge base should return the smallest evidence-backed context needed for a decision, preserve the source trail, and reuse prior conclusions safely.

1. Goals and scope

01

Fast conclusions

Select only relevant atomic Claims and Evidence to form a short candidate conclusion.

02

Avoid repeated questions

Look up question, conclusion, and decision history first; reuse a result when its conditions match.

03

Evidence guarantee

Store approved knowledge with source location, review state, and change history.

04

Context savings

Send Codex the minimum Context Pack needed for the question, not the entire document.

Scope boundary: Existing project code and collected HTML are preserved. The knowledge base is operated in its own directory; current documents are initial evidence inputs.

2. Recommended structure

The canonical source is a format-neutral knowledge graph identified by stable ID, revision, and provenance. RDF/JSON-LD and HTML, Markdown, PDF, image, video, audio, structured-data, and code representations are typed projections from the same graph. No projection may overwrite another projection or the canonical graph.

Figure 1. People maintain sources and decisions; indexes are generated; Codex supplies review and feedback.

3. L0–L5 layer mapping

In Karpathy's LLM Wiki, raw sources are immutable origins, the maintained wiki is cumulative synthesis, and AGENTS/schema is the operating contract. This design maps them as follows.

LayerRoleWiki counterpart
L0 Raw BlobImmutable original, binary, and hash.raw sources
L1 Source/MediaURL, version, rights, access time, and format.source catalog
L2 EvidenceSpan, cell, page, bounding box, timecode, query slice, or code line.source-grounded notes
L3 Knowledge GraphConcept, Claim, Relation, conflict, and supersession.interlinked maintained wiki
L4 Conclusion/DecisionQuestion, conclusion, review, curator promotion, stale, and abstain.cumulative synthesis and human involvement
L5 ProjectionsIndex, log, lint report, Context Pack, and all output formats.index-first, append-only log, lint

Queries read the L5 index first and open only required L3/L2 records. Every ingest, query, review, and rebuild appends to a provenance log. Lint checks orphan records, broken locators, stale dependencies, hidden conflicts, and projection drift.

4. Context Pack contract

CONTEXT_PACK
question: normalized query + scope + as_of
claims:
  - id: claim-...
    statement: short atomic claim
    evidence: [evidence-...]
    source_revision: revision-...
    locator: reproducible source selector
    status: accepted | conditional
opposing_evidence: []
uncertainty: explicit missing, stale, or conflicting items
decision: answer | conflict | abstain

Exclude full source text, duplicate explanations, and already-reviewed background. Include direct and opposing evidence first. Store the Pack itself so the next question can reuse it. IDs alone are insufficient: include each Claim's short statement, Evidence excerpt, exact locator, Source revision/hash, and conditions.

5. Retrieval and conclusion rules

Normalize target, relation, reference date, scope, and output format. Reuse a prior conclusion only when the canonical question key and dependency digest are current. Rank candidates by directness, authority, freshness, scope fit, independent agreement, locator quality, expected information gain, and retrieval cost.

candidate_priority(claim) =
  relevance * source_quality * freshness * scope_fit
  * independent_agreement * locator_quality
  + lambda * expected_information_gain
  - mu * retrieval_cost

The score orders the next item to read; it does not establish truth or promotion. Confirm only when every core Claim has direct reproducible Evidence and unresolved conflicts do not affect the result. Otherwise return conflict or abstain.

Conclusion accuracy

Compare curator-approved results with an independent gold set; do not calculate it from Codex self-judgment alone.

Evidence coverage

Share of accepted Claims with linked, reproducible Evidence locators.

Repeat-question reduction

Share of questions answered by safe reuse of prior questions and conclusions.

Context compression

Context Pack tokens divided by full-context tokens.

Initial approval baseline: On 50 sample questions, Pack p50 ≤ 1,200 tokens, p95 ≤ 2,000 tokens, pack_tokens / full_context_tokens ≤ 0.15, conclusion p50 ≤ 3 seconds and p95 ≤ 8 seconds, direct-Evidence reproducibility ≥ 95%, and conclusion accuracy ≥ 90%. Measure abstention separately. These are operating baselines, not proof of general performance.
